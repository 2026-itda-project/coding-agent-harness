# Jev v2 — 기존 120개 확대 평가

고정된 v2 영어 instructions/criteria로 기존 한국어 발화 120개를 각 1회 평가했다. 정답 일치는 102/120(85%)이며 dev와 test 모두 51/60이다. Sonnet은 호출하지 않았다. v2의 16/16 소규모 결과를 전체 성능으로 일반화할 수 없다는 점을 확인했다.

## 평가 조건

- 원본 120개 발화·판단 대상은 유지하고, 사전에 작성한 140개 수정안에서 해당 ID의 정답을 사용했다. 정답 변경 7개는 이번 결과를 보기 전에 정해진 수정안이다.
- 추가 SPEC-01~20은 이번에 포함하지 않았다. 원래 DEFAULT 사례 중 재분류한 Spec 정답 6개는 포함한다.
- 기존 pilot과 겹치는 12개가 dev에 포함된다. test 60개는 모델 결과를 이번에 처음 평가했으나 작성자가 정답을 검토했던 합성 데이터다. 엄밀한 비공개 고객 평가셋은 아니다.
- 이번 test 오류를 보고 프롬프트를 수정하면 같은 test 점수는 튜닝 결과로 보고해야 한다. 후속 독립 검증에는 새로운 사례가 필요하다.

## 관찰과 다음 개선 방향

- 필수 질문 누락 13개: 핵심 흐름 누락 3개, 명시 요구 충돌 9개, 지원 스택 충돌 1개. 질문을 적게 하는 것만으로 좋은 사용자 경험이라고 볼 수 없다.
- 이미 명시된 요구와 맥락 해소 사례는 각각 20/20이었다. ai_refine도 14/14로, 기본적인 충분함과 사소한 보완은 비교적 잘 구분했다.
- 충돌 사례에서는 영구 삭제와 복구, 마감 후 제출 금지와 허용 등 양립 불가능한 내용을 ready로 보낸 문제가 있다. 다음 v3 후보는 명시 충돌을 독립 질문으로 검사하는 방식이다. 아직 구현·실행하지 않았다.
- 일반 UI 표현·정렬이 Spec인지 AI 보완인지의 경계도 잔여 문제다. 이번에 정답을 사후 변경하지 않았다.
- Sonnet은 같은 120개를 평가하지 않았으므로 Sonnet보다 좋거나 나쁘다는 비교 결론은 내리지 않는다.

## 응답 검증 중단과 복구

58번째 EXPLICIT-18의 확률 합계가 0.99여서 기존 합계 검증이 실패했다. 반환된 확률이 소수 둘째 자리로 반올림돼 생길 수 있는 오차를 처리하도록 검증기를 수정했다. 항목당 0.005의 반올림 허용량을 합산하며 원본 확률은 정규화하거나 변경하지 않는다.
첫 로그의 58개 응답은 오프라인으로 재검증하고 남은 62개만 별도 실행했다. 총 실제 호출 120회이며 중복 유료 호출은 없다. 첫 로그의 오류 기록은 그대로 보존하고, 통합 결과에 validation_note를 남겼다. 단가·프롬프트는 변경하지 않았다.
원본 로그는 results/compare-v2-120-live-01 및 compare-v2-120-live-02에 Git 제외로 보관한다. 통합 config에는 두 로그 해시와 실행 헤더를 포함한다. 이번 계산 비용은 응답 usage 기준이며 청구서 조회값이 아니다.
