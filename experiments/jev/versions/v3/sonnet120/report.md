# Sonnet 단독 vs Jev v3 — 동일 120개 비교

Sonnet 5.5는 **114/120(95%)**, 저장된 Jev v3는 **110/120(91.67%)**였다. Sonnet이 4개 더 맞혔지만 Jev가 맞히고 Sonnet이 틀린 사례도 2개 있었다. Jev의 순수 판정 비용은 Sonnet의 약 1/53.6, 지연 중앙값은 약 1/8.94였다. v4 튜닝은 하지 않았다.

## 비교 조건과 한계

- 같은 한국어 입력·판단 대상·사전 수정 정답·순서 120개. 입력에는 사례 유형·정답·이유를 넣지 않았다. 각 1회.
- Sonnet은 v2 영어 4분류 지시/기준, claude-sonnet-5-5, Structured Output, max_tokens=1024, thinking API 기본값을 사용했다.
- Jev v3는 동일한 기본 4분류에 독립 충돌 검사를 추가한 저장 결과를 사용했다. 추가 Jev 호출은 없었다.
- 구성 간 비교이며 동일 구조에서 모델만 교체한 실험은 아니다. 같은 영어 4분류의 Jev v2는 참고로 102/120(85%)이다.
- 기존 test 오류까지 보고 Jev를 개선한 합성 평가셋이며 신규 독립 검증이 아니다. 4개 차이의 통계적 우월성이나 실제 UX 향상을 입증한 결과는 아니다.

## 서로 다른 강점과 공통 실패

- Sonnet만 정답 6개: CORE-05·07, DEFAULT-04·16·20, SCOPE-12. 핵심 흐름 누락, Spec 경계, 지원 스택 확인을 더 잘 처리했다.
- Jev만 정답 2개: CONFLICT-10(삭제·복구 충돌), CONFLICT-16(명시된 무승부 예외). Sonnet은 전자를 ready, 후자를 ask_user로 분류했다.
- 둘 다 오답 4개: CORE-11, DEFAULT-02, DEFAULT-10, CONFLICT-14. 특히 모호한 입력과 Spec 경계에는 평가 기준 재검토도 필요하다. 이번 결과의 정답을 사후 변경하지 않았다.
- 둘 다 정답 108개. 두 모델의 정답 합집합 116개는 정답을 알고 사후 선택한 값이며 혼합 파이프라인의 성능으로 보고하지 않는다.

## 비용과 검증

Sonnet 120회 모두 정상 완료, 자동 재시도·fallback 없음. 입력 124,484토큰 × USD 2/M + 출력 3,208토큰 × USD 10/M = **USD 0.281048**이다. 사전 예상 USD 0.6–1.2, 실행기 예산 USD 1.20보다 낮았다.

이전 v0는 16개에 입력 32,403·출력 3,657토큰이었다. 이번에는 요청당 평균 입력 약 1,037·출력 약 27토큰으로 이전 약 2,025·229보다 적었다. 영어 프롬프트와 응답량 등 실행 조건 차이가 있어 비용 감소를 단일 원인으로 단정하지 않는다. 실제 청구서·세금·환율은 확인하지 않았다. 전체 실험 기록상 누적 계산 비용은 USD 0.427666414다.

오프라인 테스트 37개 통과. 실제 로그의 코드 해시, 결과 120개 중복 없음, Jev와 정답 일치, 전부 정상 응답을 확인했다. 인증정보·원본 thinking은 정제 결과에 포함하지 않았다.

## E2E로 넘길 판단

이 평가셋에서는 두 구성 모두 목표 범위(90–95%)에 들어왔다. v4 점수 튜닝은 멈추고 다음 단계로 넘어갈 근거는 확보했지만 제품 도입 확정은 아니다. 기본 E2E를 진행하면서 Jev를 연결한다면 사용자 원문·AI 출처·Review와 Sonnet 재검토를 유지하고 전체 흐름에서 실제 질문 수·재검토 비용·생성 결과를 측정해야 한다. confidence가 높아도 틀린 사례가 있으므로 낮은 confidence 재검토가 모든 오류를 잡는다고 가정하지 않는다. 새 독립 사례 검증은 남겨 둔다.
