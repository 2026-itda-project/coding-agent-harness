# Jev v1 — 판정 프롬프트 정리

v0 커밋: 1db62a1. v0 파일·정답·결과는 보존한다.

가설: 후속 라운드/AI 생성 정책이 판정 지시에 섞여 있고 분류 경계가 넓어 ai_refine 쏠림이 생겼을 수 있다. 원인은 미확정이다.

변경 요소는 판정 프롬프트(instructions+criteria)다. 한국어, Jev 모델, 4개 라벨, 대상 state, 16개 dev 사례와 정답, 1회 실행은 그대로 둔다. 질문 라운드·confidence 후처리는 제거하고 판단 대상 한 항목에 집중한다. 명시 요구 충돌→이미 결정됨→구현 방법→사소한 제품 보완의 구분을 명확히 한다. 구체적 정답 예시를 추가하지 않는다.

이번은 프롬프트 묶음의 개선 여부를 확인하는 실험이다. 개선돼도 지시 삭제·판단 순서·criteria 중 어느 변화가 원인인지 개별적으로 입증한 결과는 아니다.

Jev만 16회 호출하고 Sonnet v0 응답은 저장된 기준선으로 비교한다. Sonnet에 새 프롬프트를 적용한 공정한 동시 재비교가 아니므로 '동일 프롬프트에서 Jev가 Sonnet과 동등'이라고 주장하지 않는다.

사전 판단 기준: v0 7/16 대비 일치 수, 필수 질문 4개 회수, 과잉 질문, ready/Spec 구분 개선, confidence<0.6 비율을 확인한다. Sonnet v0의 15/16은 목표 참고치이고 이 dev 표본에서 달성해도 도입을 확정하지 않는다. 결과를 보고 정답을 바꾸지 않는다.

Jev 비용만 발생한다. 누적 비용과 다음 호출 예상치를 비교하는 예산은 USD 0.01로 줄인다. 자동 재시도·fallback 없음. 실행 전 요청 크기 기반 예상 비용을 안내한다.
