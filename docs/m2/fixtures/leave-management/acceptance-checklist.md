# 휴가관리 예시 — Acceptance Checklist

고정 PRD(`prd.json`, 출처 `provenance.json`)의 AC를 사용자 흐름별로 묶은 판정표다. 휴가관리는 검증용 예시이며 Harness 코드에는 이 내용이 들어가지 않는다.

- 자동 판정: E6가 Spec `checks`의 HTTP 점검을 실행한 결과(`artifacts/verify.json`). 해당 AC를 덮는 점검이 모두 통과해야 한다.
- 수동 판정: `--keep-running` 미리보기에서 사람이 확인. 결과는 실행 기록에 날짜와 함께 적는다.
- 한 항목이라도 실패하면 E2E 실패로 기록한다. 빌드 성공만으로 통과 처리하지 않는다.

| 흐름 | 확인할 것 | AC | 판정 |
| --- | --- | --- | --- |
| 공통 | 첫 실행 시 샘플 연차와 대기/승인/반려 신청이 보이고, 재시작·새로고침 후에도 변경한 데이터가 남아 있다 | AC-014 | 자동 + 수동 |
| 공통 | 상단 역할 전환으로 직원/관리자를 바꾸면 현재 역할이 보이고 역할별 기능만 노출된다 | AC-012 | 수동 |
| 공통 | 직원 역할로 승인/반려 API를 부르면 거부된다 | AC-013 | 자동 |
| 직원: 신청 | 종류·시작일·종료일·사유로 신청하면 내 목록에 '대기'로 나타난다 | AC-001, AC-003 | 자동 + 수동 |
| 직원: 신청 | 종료일이 시작일보다 빠르거나 필수값이 비면 거부되고 오류가 보인다 | AC-002 | 자동 + 수동 |
| 직원: 신청 | 남은 연차를 넘는 연차 신청은 거부된다 | AC-005 | 자동 |
| 직원: 취소 | 대기 중 신청을 취소할 수 있고 관리자 대기 목록에서도 사라진다. 처리된 신청에는 취소 버튼이 없다 | AC-010 | 자동 + 수동 |
| 관리자: 처리 | 대기 목록에 신청자·종류·기간·사유가 보이고 처리된 신청은 빠진다 | AC-006 | 자동 + 수동 |
| 관리자: 처리 | 승인하면 직원 화면에서 '승인'으로 보인다 | AC-007 | 자동 + 수동 |
| 관리자: 처리 | 사유와 함께 반려하면 직원 화면에 '반려'와 사유가 보인다 | AC-008 | 자동 + 수동 |
| 관리자: 처리 | 처리된 신청에는 승인/반려 버튼이 없다 | AC-009 | 수동 |
| 관리자: 일정 | 승인된 휴가가 직원명과 기간으로 목록에 보인다 | AC-011 | 자동 + 수동 |
| 직원: 결과 | 총·사용·남은 연차가 보이고 승인 시 남은 연차가 신청 일수만큼 줄어든다 | AC-004 | 자동 + 수동 |
| 전체 흐름 | 직원 신청 → 관리자 승인 → 직원 결과 확인을 막힘 없이 완료한다 | AC-015 | 수동 |

자동/수동 구분은 계획이며, 실제로 어떤 AC가 HTTP 점검으로 덮였는지는 생성된 Spec의 `checks.ac_ids`로 확인한다.
