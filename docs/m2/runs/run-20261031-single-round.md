동네 공방의 소규모 수업 예약 서비스를 입력했다. 이용자의 수업 조회·예약·확인·취소와 운영자의 수업 등록·예약 명단 조회를 명시하고, 주 역할과 예약 확정 방식을 질문하도록 했다. 예시 수업 3개와 예약 데이터, 새로고침 후 저장 유지를 요청했다. 결제·이메일·실제 로그인은 제외했다.

## 첫 시도: 질문 생성 요청에서 중단

1. 요구사항 추출 성공: 요구사항 16개.
2. Gap 분석 성공: Gap 6개.
3. 질문 계획 요청이 HTTP 400으로 거절됨: `output_config.format.schema: For 'array' type, property 'maxItems' is not supported`.

`QuestionPlan.questions`의 Pydantic `max_length=5`가 JSON Schema의 `maxItems`로 변환되어 Claude Structured Output 요청에 포함된 것이 원인이다. 질문 내용 생성이나 사용자 답변 단계까지 도달한 실패가 아니다.

질문 생성 이후의 Review·PRD·Spec·Plan·코딩·Docker 실행은 시작하지 않았다. 브라우저는 오류를 표시했고 자동 재호출하지 않았다.

## 수정과 무료 재검증

공통 `output_schema()`에서 API에 전달하는 `maxItems`를 제외했다. 제품 프롬프트의 최대 5개 지침과 Pydantic의 `max_length=5` 검증은 유지한다. 6개 이상 응답을 잘라서 통과시키지 않는다.

회귀 테스트는 수정 전 `maxItems`가 포함되어 실패하는 것을 확인했고, 수정 후 API 스키마에서 해당 키가 빠지면서 내부 모델은 5개를 허용하고 6개를 거부하는 것을 확인했다. 전체 백엔드 오프라인 테스트 159개가 통과했다.
